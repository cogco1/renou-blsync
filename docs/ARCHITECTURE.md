# 架构（框架初稿 v0.1，2026-10-09）

需求原文和用户的拍板记录在 `需求_按D5分工.md`，本文只讲代码怎么分层、数据怎么流动、以后往哪里扩。

## 一句话

照 D5 LiveSync 的分工：Blender 管“放什么、放哪、长什么样”，UE 管“看起来怎么样”。两边靠**实例 id** 和**材质槽名**对应，中间只传一份累计的覆盖文件，外加改过的单件网格。

## 分层

```
 Blender                                        服务器 / UE 编辑器
┌──────────────────────────────┐               ┌───────────────────────────────────┐
│ 插件 renou_blsync（LS01）     │               │ ue/Content/Python/bl_sync.py       │
│  ├ live.py   实时开关         │               │  请求通道入口（attach/watch/reset） │
│  │   depsgraph 只打标记       │               │                                   │
│  │   定时器 → build()         │  覆盖文件      │ bl_sync_core.py                    │
│  │   工作线程 → deliver()     │ ───────────▶ │  每 0.1 s 看一次文件               │
│  │              wait_receipt()│  + 单件 GLB    │  按 id 原地改 HISM 实例            │
│  ├ ops.py    载入/发布/还原/定稿│  （本机经 ssh） │  重导单件，材质按槽名沿用 UE        │
│  └ ui.py     面板             │               │  批次子关卡只读，视效照常存盘        │
│                              │  status.json   │                                   │
│ 函数库 renou_blsync_lib.py    │ ◀─────────── │  回执：rev、延迟、计数、错误        │
│  （唯一一份；工程脚本直接用它）│               └───────────────────────────────────┘
└──────────────────────────────┘
```

- **函数库是底座。** 工程的摆楼脚本和插件调的是同一个库；插件本身不算任何东西，只负责“什么时候发”。
- **主线程和工作线程的分工：** 凡是读写 Blender 数据的（`overrides()`、`build()`、`export_part()`）都在主线程；写文件、ssh 推送、等回执在工作线程。同一批只保留最新一份待发文档，慢网络不会积压旧状态。
- **实时开关：** depsgraph 回调只打标记，定时器（默认 0.25 s）合并后发一次。和上次发的内容完全一样就不发。编辑模式里改的网格，要等退出编辑模式才写回网格数据，所以那时才导出。
- **网格是否真改了：** 用 `mesh_sig()`（顶点坐标、面的顶点索引、材质槽名做 SHA-256）判断，只有签名变了才导出，进出编辑模式、选择都不会触发导出。

## 文件格式

| 格式 | 谁写 | 谁读 | 要点 |
|---|---|---|---|
| `renou-placements/1` 摆放表 | 工程（正式发布） | 函数库、UE | 每个实例有稳定的 `id`；Blender 世界坐标，米，Z 朝上，四元数 wxyz |
| `renou-overrides/1` 覆盖文件 | 函数库 | UE | **累计**：和摆放表不同的全部列出，改回原样的去掉；原子写入；`rev` 只增不减 |
| 单件 GLB `<part>_<sha8>.glb` | 函数库 | UE | 只含一个件，单位矩阵，glTF Y 朝上；文件名带内容哈希，同一份不重导 |
| `status.json` 回执 | UE（测试时用假接收器） | 函数库 / 插件 | `rev`、`latency_s`、`counts`、`errors` |

## 不变量（改代码时不能破）

1. 同步永远不碰 UE 管的东西。Blender 的材质只传槽名，不传材质本身。
2. 覆盖文件是累计的，UE 重启后读一次就能恢复到当前状态。
3. 一批同一时刻只有一个写入者。
4. 正式摆放表和 `/workspace/shared/` 下的任何文件都不改；定稿只生成新版本文件，交工程发布。
5. 不开网络端口，不存凭据，不加第三方依赖。

## 以后往哪扩（对应需求第 5 节的三步）

| 步骤 | 做法 | 改哪里 | 状态 |
|---|---|---|---|
| ① 楼的摆放、换件、改单件形状 | 现有这套 | — | 已通，接入视效编辑器中 |
| ② 新的独立大件直接进 UE | 新模型 = 新件 + 新实例，放进一个“独立件”批（每个区一批），不另起格式。函数库已有 `add_object(obj, part, era='both', src='')`：复制本地网格、保留世界 TRS，生成新实例并导出只有槽名的单件 GLB。UE 侧读“槽名 → 材质”映射表（`renou-slotmap/1`，视效维护），表里没有的槽名用醒目的占位材质，并写进回执 | 函数库、UE 侧、映射表格式 | Blender 侧已做；UE 对象层与映射仍待 issue / 实测 |
| ③ 地形、道路、地面 | 地面切块，每块是一个件、一个实例，改哪块重导哪块（就是①的单件重导）。UE 收到以后，取改动实例新旧包围盒的并集，只在这个范围内重跑相交的 PCG 组件（草、植被、碎石） | UE 侧加“受影响范围 → 重跑 PCG”的钩子 | 待做（issue） |
| 视角联动（可选） | Blender 视口相机 → UE 预览相机，可开关；命名相机一键变成 UE 书签 | 插件 + UE 侧 | 待做（issue） |

## 测试

- `tests/test_lib_mock.py`（56 项）：函数库完整流程、新物体/材质槽名导出（含无槽、空槽和派生件）、父变换与三轴缩放回读；通过 `tests/fake_ssh.py` 在本地模拟远程推送，检查 GLB 去重、变化后重推、原子写入和回执，不连接真实服务器。
- `tests/test_addon_mock.py`（19 项）：插件的实时开关、监听、Shift+D、手动删除、网格签名、定稿、暂停、还原、卸载。
- 都用 `tests/make_fixture.py` 生成的合成方盒，加上 `tests/mock_ue_receiver.py` 这个假 UE；GitHub Actions 每个 PR 自动跑。
- UE 侧没法在 CI 里跑，由服务器上的 Claude 会话用 `tests/ue_probes/` 实测。
