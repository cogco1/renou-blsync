# LS01 v2 · Blender 实时预览插件（实时开关）　[CPU]

发件：人偶之心·协调。规格由「Blender→UE 实时预览」会话起草，2026-10-09。
本版取代旧的 `SPEC_Blender侧插件.md`。依据是用户确认的 D5 LiveSync 式分工（需求校准 v2 的 R5–R7）。
领取方法、规矩照 `00_算力池/README_先看这里.md`。要用 Blender 5.2.2 官方版，不需要 UE，也不需要 GPU，内存 2 GB 以内。

## 1. 要做什么（一句话）

做一个 Blender 插件 `renou_blsync`。它就像 D5 的“开始/暂停 LiveSync”开关：开着的时候，Blender 里属于 Blender 管的变化都自动写进覆盖文件，不管是脚本改的还是人手改的。UE 那边已经有接收器，0.1 秒内就会更新画面。
插件**不是拖动工具**。拖动时画面跟着动只是附带效果。

## 2. 分工（照 D5，不能越界）

| Blender 管，插件负责发布 | UE 管，插件一律不碰、不读、不发 |
|---|---|
| 实例用哪个零件、位置、旋转、缩放、复制、删除；零件本身的网格 | 材质、灯光、天空和雾、后期、植被、水、相机、关卡 |

只往一个方向推：Blender → UE。

## 3. 底座：已经有的函数库（直接 import，不要重写）

`renou_blsync_lib.py`（本目录）已经在服务器上和 UE 联调通过。下面这些都在里面：
- 载入批；
- `load_meshes=False` 时只读 GLB 头里的包围盒；
- 按楼分组；
- 绕楼中心转；
- 换件；
- 单件导出；
- 累计写覆盖文件（`publish`）；
- 读 UE 回执；
- `write_back` 定稿；
- 本机经 ssh 推到服务器（`remote=`）。

插件只做三件事：**实时开关 + 变化监听 + 面板**。
如果发现函数库有 bug 或者缺函数，可以在你的副本里改，但要在 README 里逐条写清改了什么、为什么改，交回来由我合并。

覆盖文件的格式 `renou-overrides/1` 写在函数库的文件头里。参考实现是 `bl_live_test.py`：无界面，七步改动，每一步都等回执。

## 4. 功能

| 编号 | 功能 | 要点 |
|---|---|---|
| F1 | 载入 | 面板上选摆放表和零件 GLB，可选“只载包围盒”（`load_meshes=False`）。调用 `Batch(...)` 即可。同一个 .blend 存盘、重开以后，插件能认出已经载入的批（批信息存在 Scene 自定义属性里），不需要重新载入。 |
| F2 | 实时开关 | 开：`depsgraph_update_post` 只负责做标记；`bpy.app.timers` 每 0.25 秒检查一次，有标记就 `publish()`，但 `wait=0`，不要卡住界面。回执另外用定时器去读。关：不发布。重新打开时立刻补发一次（文件是累计的，补一次就齐了）。只有 Blender 管的东西变了才发：物体的矩阵、`blsync_part`、删除、复制、零件网格。改材质、灯光、相机都不触发。 |
| F3 | 手改也算 | 人手 G/R/S、Shift+D、X 删除，和脚本调用一样会被发布。复制出来的物体会带着原件的 `blsync_id`：靠 Scene 里一张 id→物体 的指针表认出哪个是原件，给新物体分配新 id `<批>_bl<序号>`。这一块请沿用 Acacia「Blender_UE同步实验」里 UUID 加 Scene 指针表的做法（`scripts/publisher.py`）。删除的判断方式：原表里有，但场景里已经找不到。 |
| F4 | 改网格 | 零件网格被编辑过，就只导出这一件（`export_part`）。判断“改过”用网格内容哈希，覆盖顶点、面、UV、材质槽名，摘要函数沿用 Acacia 实验的写法。注意：真实零件有 UV、贴图和多个材质槽，不能照搬实验里的白名单拒绝规则。 |
| F5 | 回执 | 面板显示 UE 最近一版的 rev、`seconds`、`latency_s`、`counts`；`errors` 不为空时标红。 |
| F6 | 本机模式 | 设置里填 `remote`，例如 `myserver:/workspace/jobs/look-blsync-20261009-01/data`，就走函数库的 ssh 推送，同样在后台定时器里做，不卡界面。不存任何密码。默认留空。 |
| F7 | 定稿 | 按钮“写回摆放表”，调用 `write_back`。 |
| F8（可选） | 视角 | 把 Blender 视口相机或命名相机写进覆盖文件的 `"view"` 字段：`{"name","pos","quat_wxyz","lens_mm","sensor_mm"}`。UE 侧以后再接。这一项只做 Blender 侧，默认关。 |

## 5. 不做

- UE → Blender 回传；
- 材质和灯光同步；
- 地面块、远景块；
- 读写 `/workspace/shared/`；
- 网络监听；
- 账号凭据。

## 6. 自测（交付前自己跑完，全部要有断言）

本目录的 `mock_ue_receiver.py` 是一个假的 UE 接收器：盯着覆盖文件，检查格式，再像 UE 一样写 `status.json`。所以没有 UE 也能把回执这条链测通。
测试数据用本目录的 `area_01_04_placements.json` 和 `area_01_04_parts.glb`（65 MB，1,825 个实例）。

无界面测试脚本要覆盖下面这些情况，每一步都检查覆盖文件内容和假接收器的回执：
1. 载入，两种模式都测；
2. 开关打开以后，脚本挪一栋楼会自动发布；
3. 人手式改动：直接改 `matrix_world` 来模拟，也会发布；
4. 复制，检查 id 修复；
5. 删除；
6. 换件；
7. 改一个零件网格，确认只导出 1 个 GLB；
8. 关掉开关后改两处，不发布；再打开，一次补齐；
9. 撤销（`bpy.ops.ed.undo` 或复位）；
10. `write_back`：把新表重新读一遍，没改的实例逐字段和原表一致；
11. 存 .blend，重开，插件认出批，继续发布。

性能也要量：载入时间、一次发布的耗时。另外用 7,500 个实例（把 area_01_04 复制 4 份造数据）测一次比对加发布，要在 50 毫秒以内。
