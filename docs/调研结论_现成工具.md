# Blender→UE 实时预览：现成工具调研（一页）

2026-10-09 纽约 12:35，「Blender→UE 实时预览」会话。只读了网页，没装、没买任何东西，禁用名单里的工具一个没碰。

## 结论

现成工具里，没有一个能同时满足这四条：UE 5.8 加 Blender 5.2、跑在 Linux 服务器上、认我们的摆放表（`renou-placements/1` 加 HISM）、只同步改了的部分。
所以我们自己写了一层小同步，已在测试副本上跑通：

- 在 Blender 里改一处，UE 里生效要 **0.08–0.20 秒**。
- 现在的办法是整块重导。光 UE 里导入 area_04_03（410 MB）这一步就要 **70.6 秒**，Blender 导出和上传的时间还没算在内。

## 选的方案：覆盖文件加 HISM 原位更新（自写，已测通）

- **Blender 侧**：写一个累计的覆盖文件 `<批>_overrides.json`（`renou-overrides/1`），列出和正式摆放表不一样的实例：挪位、换件、复制、删除，可选附上单独重导的零件 GLB。写文件用原子替换。
- **UE 侧**：`bl_sync_core.py` 监听这个文件，按实例 id 找到 ct_placements 建好的那个 HISM 实例，原地改变换、换件、隐藏或新增。不重导、不存关卡。接上时会逐个核对 708 个实例和摆放表是否一致，误差为 0.0 cm。
- **Blender 和 UE 都在服务器上**时直接写文件。Blender 在笔记本上时，用 scp 推一个几 KB 的文件过去。全程不开端口，不碰凭据。
- **还差两样**：
  - Blender 侧的交互插件：载入批、拖动时实时发、换件、单件网格重导、写回摆放表。规格已经写好，按用户的意思交给下午新来的第三个 bot。
  - “改了的网格单独重导”的 UE 侧实测。
