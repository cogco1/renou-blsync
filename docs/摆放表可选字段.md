# renou-placements/1 的可选字段

2026-10-10 用户同意、协调批（依据：程序化布景调研 §4.9、§7 第 2 条）。格式名不变，仍是 `renou-placements/1`。下面这些字段都是可选的，向后兼容：旧文件照样能读，没有这些字段的行照旧处理。

## 字段

| 字段 | 取值 | 用途 |
|---|---|---|
| `layer` | `L1`–`L5`、`HERO`（L0 地面层不进表） | 分层检查、分层导入 |
| `recipe` | 配方或模板代号，如 `F_QUAY_LOAD`、`V2` | 追查和统计 |
| `group` | 团或小场景的实例 id，如 `g012` | 整组选、整组删、整组锁 |
| `pair` | 另一时代对应实例的 id | 过去和现在互相追溯 |
| `event` | 做旧事件 id（只在现在版） | 做旧追溯 |
| `lock` | `"hand"` 或 `true`：重新生成时保留这一行；`"proc"`、`false` 或不写：生成器可以重算 | 重跑时保留手改 |
| `tags` | 字符串列表，如 `["clutter", "nocol"]` | 随机删、碰撞等 |

## 读取方的规则

- 所有读取方都忽略自己不认识的字段，包括今后新加的字段。
- 函数库 `renou_blsync_lib`：
  - 载入时，可选字段挂在物体上（`blsync_meta`）。`Batch.meta(o)` 取回这些字段。
  - `Batch.where(layer=…, group=…, tags=…, lock=…)` 按字段选物体；`Batch.group(key)` 也会匹配 `group` 字段。`is_locked(row)` 判断一行是否锁定。
  - `write_back()`：
    - 没改的行原样保留，未知字段也保留；
    - 挪过、换过件的行，保留原有字段，并写上 `lock = "hand"`；
    - Blender 里复制出来的新行，继承原件的 `layer`、`recipe`、`group`、`event`、`tags`，不继承 `pair`，并写上 `lock = "hand"`；
    - `write_back(..., lock_edits=False)` 不写 `lock`。
- UE 里的 bl_sync：只用 `id`、`part`、`pos`、`quat_wxyz` / `yaw_deg`、`scale`、`era`、`lods`。可选字段按实例记下，`where` 动作会在 `meta` 里返回；同步不依赖它们。
- 覆盖文件 `renou-overrides/1` 不变：可选字段属于摆放表，不进覆盖文件。

## 过渡

批下来之前，规则脚本可以先把这些写进 `src`，例如 `src="L3;F_QUAY_LOAD;g012;E-H3-1"`。改用正式字段以后，`src` 恢复原来的用法。

## 测试

- `tests/make_fixture.py`：BLD_05 的 4 行带全部可选字段；BLD_06 的一行带一个谁都不认识的 `x_future`。
- `tests/test_lib_mock.py` 检查了：
  - `where` 和 `group` 能按字段选物体；
  - 字段挂在物体上；
  - `is_locked` 判断正确；
  - 挪过的行保留字段、写上 `lock = hand`；
  - 复制的行继承字段、不继承 `pair`；
  - 没改的行（含 `x_future`）原样保留；
  - `lock_edits=False` 不改 `lock`。
- UE 测试编辑器（`examples/server/fields_test.sh`）：带可选字段和未知字段的底表照常挂接、照常应用覆盖；`where` 返回 `meta`；逐个核对 708 个实例，0 处不符。
