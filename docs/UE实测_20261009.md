# UE 实测记录 2026-10-09（接入视效 live 编辑器）

测试人：「Blender→UE 实时预览」会话。场景是视效的 live 编辑器（UE 5.8.3，Linux），关卡 `/Game/Shots/S02/L_S02`（27 格实例化正式版），现在时代，观感 V4。
测试批次 `area_04_03`，708 个实例，666 个 HISM，是 CBD 填充街块所在的那一格；批次层是流送子关卡 `/Game/Inst/area_04_03/L_area_04_03`。
Blender 侧用 `blender/renou_blsync_lib.py`。脚本见 `examples/server/vis_live.py`、`r3_live_set.py`。

## 延迟：Blender `publish()` 发布到 UE 生效

| 操作 | 端到端 | UE 侧处理 |
|---|---|---|
| 挪一栋（BLK_001 往东 60 m） | 0.003–0.09 秒 | ≤ 3 毫秒 |
| 换件（BLK_004 换成 BLK_002 的零件） | 0.02–0.08 秒 | ≤ 1 毫秒 |
| 单件网格重导（零件加高 25%） | **17.1 秒** | 17.07 秒，全部花在 Interchange 导入上 |
| 复位 | 0.04–0.08 秒 | ≤ 11 毫秒 |

单件重导在不出画面的测试编辑器（-nullrhi）里只要 0.9 秒，正式场景慢得多，原因应该是导入时还要建距离场等渲染数据。已单独开 issue 跟进。

## R2：同步不碰 UE 管的东西

- **材质**，用 `materials` 动作逐槽核对：
  - 挪位：不变。
  - 换件：同名槽保持原样；新出现的槽按批里已有的 MI_C_ 套，和视效的 `slot_to_mi_v1` 表一致。
  - 重导：11 个槽全部沿用原来的 MI_C_（标记为 carried）。
  - 复位：和原样逐槽一致。
  - 全程没有用到占位材质。视效对比截图后确认颜色一致。
- **场景指纹**（`fingerprint`）：一整轮同步做下来（重开 → 监听 → 应用 → 清空 → detach → 再 attach），前后的哈希完全一样，都是 `8eb8b8f78331456b`。比对范围包括灯光、天空、雾、后期、云、8 个相机、3 个水体、4 个 Landscape，以及 40,204 个不归同步管的材质槽。
- 存盘前和重开后的指纹不一样，差异全部来自编辑器重启：84 个地形草组件重新生成，切换脚本重建了 P1 相机，切时代时草地关卡重新加载。和同步无关，视效已确认。

## R3：预览期间可以存盘，存盘不会混进预览

1. 预览开着：BLK_001 往东 60 m，BLK_002 原地转 15°。此时 `L_area_04_03.umap` 被设为只读。
2. 视效照常存盘：存了 L_S02 和 49 个材质包，批次层被锁着，存不进去。
3. 关掉编辑器，重开 L_S02。
4. 检查结果：
   - attach 时核对 708 个实例，和正式表误差 0.0 cm；
   - 批次层文件的 SHA 前后都是 `11baa01d…`，修改时间也没变；
   - 开始监听后，预览状态自动恢复。
5. 清空覆盖文件后，只读自动解除；detach 后文件权限恢复成 `rw-r--r--`。

## 结论

UE 实测通过。主路线“脚本摆楼 → UE 实时看”可以用了。已知问题只有一条：单件网格重导在正式场景要 17 秒。
