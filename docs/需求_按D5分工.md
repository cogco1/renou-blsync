# Blender→UE 实时预览：需求校准 v2（按 D5 LiveSync 的分工）

2026-10-09，协调根据用户的纠正写。这一版取代 `SPEC_Blender侧插件.md` 和 `使用说明_Blender改_UE看.md` 里和本文冲突的地方。

用户原话：“为什么要拖动？不是都脚本化了吗？……编辑blender物件还是在blender，然后编辑UE还是在UE，你是要互相传递。D5就是基于UE4做的，所以你可以参考。”随后确认：“对的，你校准一下需求”。

## 1. 参照：D5 LiveSync 怎么同步 Rhino（官方文档）

- Rhino 里改的模型和材质，实时推到 D5；有一个开始/暂停的开关。
- 在 D5 里调过的材质和场景参数，同步时保留，不被 Rhino 覆盖。
- 视角默认联动，可以一键关；Rhino 的命名视图可以一键变成 D5 的镜头列表。
- 灯光同步不是实时的。推送方向是 Rhino → D5。
- 用户在论坛上反映最多的问题：同步后 D5 里调好的材质丢了，或者整个模型被替换。**我们要从设计上避开这一条。**

## 2. 分工：谁管什么

| | Blender 管（同步推过去） | UE 管（同步永远不碰） |
|---|---|---|
| 内容 | 用哪个件（part）、位置、旋转、缩放、增删；件本身的网格 | 材质（MI_C_ 及其参数）、灯光、天空和雾、后期、植被和草、水、Megascans、特效、出片和游戏的机位、关卡结构 |
| 在哪改 | Blender：脚本，或者人手改 | UE 编辑器：视效照常改，照常存 |
| 存在哪 | 摆放表（正式版由工程发布）+ 覆盖文件（预览期间） | UE 工程本身 |

推送方向只做 Blender → UE。UE 里改的东西不回传 Blender，要回传等用户提出。

## 3. 需求

### P0：今天工程恢复 CBD 摆楼之前要有

**R1 脚本是主路线。**
- 工程、建模的 Blender 脚本里调几个函数就能完成同步，不需要人点界面，也不需要人拖：载入批、按 id 找实例、改位姿或换件、发布。
- 脚本跑完到 UE 画面更新，不超过 2 秒（脚本在服务器上跑）；在本机跑的，经 scp 再加 1–2 秒。
- 同一套函数在有界面的 Blender 和无界面的 Blender 里都能用。
- 绕楼自身中心旋转用 M = T(c)·R·T(−c)，要作为现成函数提供（CBD 填充街块的网格是按世界坐标烘焙的，pos 是 0）。

**R2 同步永远不动 UE 管的东西。**
- 挪位、换件、单件网格重导之后，这些实例上的材质和正式重建时一样，按 ct_placements 正式重建的同一套规则套 MI_C_。
- 换成本批没出现过的件，也要套 MI_C_，不能显示 GLB 自带材质。现在说明里写的这条限制要去掉。
- Blender 里的材质一律不传，也不读。
- 验收：同步前后，灯光、雾、后期、植被 actor 的数量和关键参数完全一样；改动实例的材质路径和正式重建一致。

**R3 预览期间 UE 照常能存，存盘不会混进预览状态。**
- 视效在预览期间调材质、灯光，要能正常保存。保存的结果里不能有 Blender 那边的预览改动。
- 做法由实时预览会话定，比如把批次层锁住不让存，或者存盘前先自动 reset、存完再套回去。做完要测：存一次 → 关掉编辑器 → 重开 → 批次层和正式表误差为 0。
- 单件重导生成的预览资产，统一放进一个预览专用目录（例如 `/Game/_LivePreview/`）。这个目录不进 cook，不进游戏包，reset 或定稿时清理（清理指移进归档或回收站，不永久删）。

**R4 接在正式场景上。**
- 接在视效的 live 编辑器里，加载 L_S02（27 格实例化正式版）。
- 加 P1 书签，切到现在时代。
- 不另开带画面的编辑器。

### P1：今天晚些或明天

**R5 实时开关（LS01 插件重新定位）。**
- LS01 是挂在 Blender 里的监听器，对应 D5 的“开始/暂停 LiveSync”，不是拖动工具。
- 开着的时候，不管是脚本改的还是人手改的，Blender 里属于“Blender 管”的变化都自动发布。暂停后不发布，再开时一次补齐。
- 拖动中跟着发布（每秒约 4 次）这一条保留，但只是附带效果，不是主要用途。
- 面板显示 UE 回执：第几版、延迟、报错。

**R6 定稿。**
- 一条函数调用（脚本里也能用）把当前覆盖文件烘焙成 `<批>_placements_v<NNN>.json` 和 `<批>_changes_v<NNN>.md`，交工程发布。
- 工程发布后，视效按新版重建，覆盖文件 reset。重建后的画面要和预览时一模一样（实例误差 0，材质一致）。
- 插件和脚本都不碰 `/workspace/shared/`。

**R7 本机 Blender。**
- 本机笔记本上的 Blender 打开 LiveSync，用系统里已经配好的 scp 推到服务器，人在 Selkies 里看 UE。
- 插件不存任何密码或密钥。

### P2：有空再做

- **R8 视角联动：** Blender 视口相机 → UE 预览相机，可开关；Blender 里的命名相机一键变成 UE 书签。
- **R9 扩大范围：** 除了 ct_placements 的实例层，单件整模（比如枢纽塔这种独立放的大件）也能按名字挪位、换网格。

### 不做

- UE → Blender 回传。
- 从 Blender 同步材质、灯光。
- ground 地面块、far 远景块、packed 列的按 id 修改。地形和大地图调整目前整体暂停。

## 5. v3 用户拍板（纽约约 13:10）：范围扩到整个场景；散布同步后自动重算，不回传

用户先问：“你现在给我思考我的需求到底是什么，为什么我拿D5举例，我们对齐一下”。对齐后定了两条：
- **范围：整个场景都走同步。** 不再只是 CBD 摆楼的工具，而是以后所有 Blender→UE 交接的常设通道，取代“建模交给视效、视效手动换进 UE”那一圈。分三步做：
  1. 楼的摆放、换件、改单件形状。已测通，13:40 接入 L_S02。
  2. 新模型直接进 UE。门座吊、尖顶塔、班轮这类独立大件，各带一个永久 id，按材质槽名套 UE 材质。表里没有的槽名，UE 用醒目的占位材质显示，并在回执里列出来，视效补一行映射就好。
  3. 地形、道路、地面。地面切成块，每块一个 id，只重导改过的那块；改完在那一块的范围内重算草和植被（怎么算见下面 2026-10-09 的确认；手刷的植被不会跟着变）。道路先按网格同步。这一步做完，暂停的地图调整才能恢复。
- **方向（用户随后补充，纠正了上一条“只读可见”）：** “D5里改的内容，rhino里是看不到的，但实际上影响并不是很大，比方说散布，rhino更新后D5会重算，而不是再加一次同步成本”。
  - 所以 UE→Blender 的参考快照**先不做**，不额外增加同步成本。
  - 改成：**凡是依赖 Blender 几何的内容，在同步后自动重算。** 包括草、植被和碎石散布，楼脚和路边的贴地小件，以及地面块上的散布。
  - 楼挪走了，原处自动长出草；新位置自动清空，不和楼穿插。地面块改了，就在那一块的范围内重跑。
  - **2026-10-09 用户确认（经协调转达）：散布在 Blender 侧重算，只发增量**（issue #4）。工程现有的生成器（植被摆放、隐形 Landscape 的高度和草地 / 石缝 / 禁草权重）只对受影响的格子重算，产出增量：植被和碎石的增量是植被批次的覆盖文件，草的增量是 Landscape 补丁。UE 只负责应用，Landscape Grass 在被改到的组件里自己重新生成。这样规则只有一套，预览和正式重建的结果一致；多出来的那一步由脚本自动完成，人不用管。子任务见 #12–#16。
  - 只存在于 UE 的散布（比如 Megascans 草的品种和密度，由 Grass Type 决定）仍归视效，不经过同步。
  - 手刷的东西不会自动跟着变，回执里列出和新位置冲突的手刷件，由视效处理。

**新增分工：**
- 实时预览会话：UE 侧，包括新物体支持、材质槽契约，以及应用散布增量（植被批次的覆盖文件、Landscape 补丁）和手刷件冲突报告。函数库的维护者是 Ash（见 CONTRIBUTING.md）。
- Acacia（LS01）：Blender 面板和监听器。原定的“UE参考（只读）”取消。
- 视效：槽名到 MI_C_ 的映射表（slot_to_mi，已出 v1）；只在 UE 里存在的散布参数。
- bot（经 Ash 或 issue）：Blender 侧按格重算散布（#13 植被和碎石、#14 Landscape 补丁），UE 插件按矩形写入 Landscape（#15，C++）。
- 建模：交付的新模型按槽名契约命名材质槽，带 id。
- 工程：发布定稿。
